# doctrine-corpus

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.20337008.svg)](https://doi.org/10.5281/zenodo.20337008) [![Ask DeepWiki](https://deepwiki.com/badge.svg)](https://deepwiki.com/shimo4228/doctrine-corpus)

A DOI-registered dataset of question-and-answer pairs built from one author's (shimo4228) written design decisions, for people who build LLM training mixes or RAG indexes and for anyone who wants to read how those decisions were made. Each example is one Q&A in chat-message format, in English or Japanese, with metadata recording which project and which source document it came from. The sources are the architecture decision records (ADRs), theses, glossaries and structured essays of four of the author's practice lines (long-running, independently citable projects: Agent Knowledge Cycle, Contemplative Agent, Agent Attribution Practice and Authorship Strategy), plus sections of the author's published Zenn articles (222 examples).

It carries out one tactic of the author's [Authorship Strategy](https://github.com/shimo4228/authorship-strategy) project: placing an author's work where LLMs learn from it.

One `judgment` example, generated by an LLM from an Agent Knowledge Cycle ADR (`meta.source: docs/adr/0004-two-stage-distill-pipeline.md#decision`), with the answer shortened:

> **Q:** Why not just put the JSON schema directly in the system prompt of a single distillation call and have the model produce both insight and structure in one pass? It saves an LLM round-trip.
>
> **A:** The round-trip is what the design is buying. A single-stage call with a schema in the system prompt forces the model to satisfy format and reason about the episodes in the same forward pass; the schema wins and the patterns come out shallow [...] The extra call is the price of giving each stage a clean reasoning budget.

## Why a corpus, not a LoRA

A prior prototype (`disposition-lora`, 2026-05-06; see [`docs/empirical/README.md`](docs/empirical/README.md) for the retrospective) fine-tuned a LoRA adapter on 230 chunked completion examples from Zenn articles and AKC/AAP ADRs. The retrospective is explicit: *voice transferred, judgment did not*. The artifact behaved like a "shimo4228-style mannerism wrapper," not a "shimo4228 judgment oracle."

The pivot encoded in this repository:

- **Primary artifact = the corpus**, not the LoRA. The corpus is base-model-independent; a LoRA is bound to a specific base architecture and depreciates as base models turn over. See [ADR-0001](docs/adr/0001-corpus-as-primary-artifact.md).
- **The 343 `judgment` examples are judgment-eliciting, not chunk-as-completion** (training a model to continue a passage of source text). The Q states a situation and the A reaches a decision. They come from three sources: in the 226 LLM-generated pairs, the A applies the source project's own framework explicitly; in the 113 pairs extracted by script from ADRs, the Q frames the ADR's Context as the situation and the A is the ADR's own Decision text. The other 4 are hand-written pilot pairs. Most of the other examples are direct exposition: `explain` examples restate ADRs and thesis sections, `definition` examples restate glossary entries, and the 222 Zenn examples keep the prototype's form, where the Q asks for one section of a named article and the A is that section's text.
- **Bilingual pairs where the source is bilingual**. Where a source exists in both languages, each judgment example appears once in English and once in Japanese, following Authorship Strategy's bilingual convention. In v0.1.0 the judgment examples are 188 English / 155 Japanese: Agent Attribution Practice and Authorship Strategy are fully paired; Contemplative Agent has 120 / 114 because two of its source ADRs had no Japanese version yet when v0.1.0 was built; and Agent Knowledge Cycle is almost all English (28 / 1) because its ADRs have no Japanese versions (its one Japanese example is a hand-written pilot pair).
- **Per-example metadata**. `{line, source, lang, shape}` is recorded on every line so downstream consumers can ablate, weight, or filter. `shape` is the example's form: `judgment`, `explain` (exposition), `definition` (a glossary entry) or `contrast` (how two lines differ on one situation).

## Intended uses and current limitations

The corpus is designed to be used as an **ingredient**, not as a standalone fine-tuning package.

**Intended for** (designed for these uses; none has been tested, see [ADR-0001](docs/adr/0001-corpus-as-primary-artifact.md)):
- **RAG retrieval material**: bilingual judgment Q&A pairs as retrieved context for downstream LLM applications.
- **Mixing into larger instruction-tuning corpora**: 851 examples is a small addition to FLAN/Alpaca-scale mixes.
- **Human reading material**: the corpus is designed to be readable end-to-end as a reference text for the author's judgment patterns.

**Tested and failed:**
- **Standalone small-LoRA fine-tuning.** A verification LoRA (Qwen3-8B-4bit, 300 iter on 851 examples) was trained as a disposable probe and returned a FAIL verdict: it reproduced the same "mannerism wrapper" failure mode as the `disposition-lora` prototype, so the voice transferred and the judgment did not. See [ADR-0005](docs/adr/0005-stage-d-verification-lora-result.md) for the verdict and the two v0.2.0 hypotheses it records (data scale, shape distribution); it treats a larger base model as out of scope.

## Content scope (v0.1.0)

851 examples in total, distributed across the four practice lines and one source of published articles:

| Line | Examples |
|---|---:|
| Agent Knowledge Cycle (AKC) | 38 |
| Contemplative Agent | 318 |
| Agent Attribution Practice (AAP) | 146 |
| Authorship Strategy | 126 |
| Zenn articles | 222 |
| Cross-line (`shape: contrast`) | 1 |
| **Total** | **851** |

By language: 334 English / 517 Japanese (all 222 Zenn examples are Japanese).
By shape: 343 judgment / 371 explain / 136 definition / 1 contrast.

How the examples were made: 5 pilot pairs were written by hand (4 judgment, 1 contrast), 226 judgment pairs were generated by an LLM inside a Claude Code session, and the other 620 examples were extracted from the source documents by script: 238 from ADRs (113 judgment, 125 explain), 222 from Zenn articles (explain), 136 from glossaries (definition) and 24 from theses (explain). Per-source counts are in [`manifest.json`](corpus/v0.1.0/manifest.json).

The train/valid split is 766/85 (seed=42, val-fraction=0.1). The 5 pilot pairs are already folded into these 851, so do not add `pilot.jsonl` on top.

Attention, Not Self (the fifth practice line) is **excluded from v0.1.0** because its content was still a stub at the v0.1.0 release (2026-05-22). It is planned for v0.2.0 or later.

## How to consume

The corpus is distributed via:

- **GitHub (canonical)**: this repository, with the full working tree, scripts, eval and ADRs.
- **Zenodo (DOI archive)**: concept DOI + per-release version DOI; [Citation](#citation) says which to cite.
- **Hugging Face Datasets (mirror)**: [`Shimo4228/doctrine-corpus`](https://huggingface.co/datasets/Shimo4228/doctrine-corpus): the corpus files and manifest, citation metadata, changelog and AI-facing files (llms.txt, graph.jsonld), with its own dataset card in place of this README, but no scripts, eval or ADRs. Auto-converted to Parquet for direct `pandas` / `Polars` / `datasets` load.

The HF mirror is the recommended ingest path for LLM training pipelines and RAG ingestion. The GitHub repository is the place to audit the generation process.

Loading from the HF mirror gives `train`, `validation` and `pilot` splits; `validation` is `valid.jsonl`, and `pilot` repeats 5 examples that are already in the other two:

```bash
pip install datasets
python -c "from datasets import load_dataset; print(load_dataset('Shimo4228/doctrine-corpus'))"
```

The smallest look at the data needs only git; each line of a split is one Q&A example with its `meta`:

```bash
git clone https://github.com/shimo4228/doctrine-corpus
head -n 1 doctrine-corpus/corpus/v0.1.0/train.jsonl
```

- **[agent-attribution-practice](https://github.com/shimo4228/agent-attribution-practice)**: a source line on who answers when an autonomous agent fails; the `aap` examples apply its four Business AI Quadrants, which route a piece of work by whether it is deterministic or needs semantic judgment, and whether its workflow is pre-defined or exploratory.
- **[shimo4228](https://github.com/shimo4228/shimo4228)**: the author's hub, with the five practice lines (long-running, independently citable projects), four of which this corpus draws on, and their DOIs.
